# 發布與封裝

兩版獨立發布，不需要等待另一平台完成。版本、產物及平台操作見：

| 平台 | 專屬指南 | Tag |
|---|---|---|
| Windows／WPF | [Windows 封裝與發布](../windows/release.md) | `windows/v<version>` |
| Linux／Arch Qt | [Linux 封裝與發布](../linux/release.md) | `arch/v<version>` |

## 共用流程

平台 workflow 核對 annotated tag、來源 commit 和平台版本；建置失敗會停止發布。PR／main 推送不觸發這兩個發布流程。功能、桌面、效能與安裝生命週期測試依[測試指南](testing.md)另外執行。

版本直接讀取平台設定檔，文件範例使用佔位符，不另外維護目前版號。候選套件、公開發布與安裝驗證分開判定。

## 發布完成條件

自動發布只要求 tag／版本一致且建置封裝成功；功能、效能與安裝驗證改由發布者自行決定是否手動執行，不能把發布成功視為這些驗證已通過。以下清單供手動驗證與交付規劃使用。

1. 對應平台功能驗收、測試與效能紀錄齊全。
2. 建置候選套件，檢查內容、授權、相依及 hash。
3. 在有授權的乾淨環境完成生命週期驗證。
4. 經使用者授權提交、建立 annotated tag、推送與公開發佈。
5. 確認 hosted workflow 成功，發布資產、版本與 checksum 相符。

本機建置成功不代表已發佈。未設定簽章就標明未簽署，不宣稱已簽署。
