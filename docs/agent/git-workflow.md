# Git Workflow

## File Change Protocol

1. Run `git status` before you edit files. Preserve existing work.
2. Stage and change task-related files only.
3. Review `git diff` and run all fitting checks.
4. Commit to the current task branch with a short, clear message.
5. Report the commit hash in your final response.

## Safety Rules

- Do not push to remote branches without explicit instruction.
- Do not amend, rebase, or rewrite history without explicit user request.
- For read-only tasks, report your findings directly without a commit.
