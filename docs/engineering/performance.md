# 效能

## 目標

保留產品既有目標：代表性本機圖片從選取到完整原圖首次繪製提交，目標 500ms 以內。1024 預覽不能算完成。這不是任意硬體、圖片大小或儲存裝置的保證。

圖庫載入、捲動 FPS、CPU 與程序總記憶體尚無正式數值門檻。先記錄真實結果，不宣稱換框架必然更快。

## 必須保留的界限

詳細規則以[執行時不變條件](runtime-invariants.md)為準：

- 圖庫只排程可見或已實體化的靜態圖片；快速捲動淘汰過期工作。
- 解碼子程序總數最多 8，佇列與逾時都有界限；取消必須釋放實際程序及工作槽。
- 不可見的近期圖庫圖片快取最多 32 MiB、256 筆。
- PNG 磁碟快取由單一背景清理者管理；每輪保留快照最新 2,000 筆，每 5 秒只在有寫入時處理。
- Viewer 保留一張完整原圖，RGBA 上限 256 MiB；最多三張 1024 預覽，合計 12 MiB。
- 解碼緩衝、複製、WPF／Qt 圖片資源和 GPU 配置另計，不能把像素上限宣稱成程序記憶體上限。
- 10,000 筆載入與搜尋投影以單次清單重設交付 UI，不逐筆觸發 10,000 次通知。

## 平台量測

Windows 與 Arch 分開留下 Release 證據。每次記錄：

- commit、dirty state、App 版本、SDK／Qt／codec 版本與 build profile。
- OS、桌面工作階段、CPU／GPU／驅動、檔案系統與儲存裝置。
- fixture manifest、圖片數量、格式、尺寸、總容量與 hash。
- 視窗尺寸、顯示縮放、顯示／隱藏狀態、冷暖快取定義。
- App log、工作完成狀態、錯誤、未完成樣本及效能輸出。

冷 App profile 不代表清除 OS 檔案快取。暖磁碟快取與同一程序中的暖像素快取必須分開。以相同素材跨平台比較時，也要揭露硬體和渲染量測點的差異。

## 量測欄位契約

兩版第一階段先定義診斷輸出位置，效能階段完成以下欄位及 schema 版本。保留名稱時必須保留語意：

| 指標 | 定義 |
|---|---|
| `frontEnd`／`buildProfile` | WPF 或 Qt Quick、Debug 或 Release |
| library／first thumbnail／search | 記錄明確起訖點，區分掃描、投影與 UI 更新 |
| `viewerPreviewReadyMilliseconds` | 選取至可用的 1024 預覽像素 |
| `viewerSharpPaintMilliseconds` | 選取至完整原圖第一次繪製提交 |
| sharp paint count／max／samples | 每次選取最多計一次成功，保留各筆樣本與最大值 |
| target misses／unpainted selections | 超過 500ms 與到期仍無完整原圖的選取分開記錄 |
| batch counts／duration | 總數、成功、略過、取消、失敗與開始到完成時間 |
| CPU／memory | 採樣時間、百分比正規化方式、working set／RSS 與峰值 |

量測 schema 必須有版本，並記錄實際前端名稱。WPF 與 Qt 各自記錄實際的繪製提交觀測點，不能把 decode callback 當成 paint，不能宣稱量到 OS compositor 呈現。

## 必測情境

1. 空圖庫、代表性混合圖片、大型 10,000 項目資料集。
2. 初次可操作畫面、首批縮圖、連續捲動、搜尋、排序、切換資料夾。
3. 同一 Viewer 內連續前後切換、快速 A-B-A、關閉再開同張圖、大型與損壞圖片。
4. 冷／暖載入、縮圖逾時、取消、關閉 App 後的工作與暫存清理。
5. 可丟棄圖片副本上的轉檔與批次重新命名。

大型資料集不能只靠同一張小圖複製來證明真實圖片解碼效能。Viewer 中還停在預覽的樣本列為未完成，不能從統計中排除。

效能檢查不能只看程序 exit code；需核對目標超標和未完成欄位。若未達目標，保持對應 TODO 未完成並記錄原因，不自動放寬門檻。

## Arch 實測紀錄（2026-09-13）

9 檔代表性混合素材包含公開實拍照片、不同靜態格式、透明圖表與 12 MP 衍生拼圖。Release 在相同主機、無建置／私有桌面測試負載時，App 冷暖快取各 12 次完整原圖繪製提交，最大值分別為 482 ms／296 ms；超標與未完成均為 0。這是固定素材與環境的量測結果；先前同時執行建置或桌面驗證的樣本仍有超標，不能延伸為任意負載保證。

瓶頸是 preview 回傳前的 PNG 快取壓縮。內部快取改用 compression 0 的無損 PNG；既有 PNG 仍可讀取，來源與匯出品質不變。代價是磁碟快取較大，原有 2,000 檔上限不變。完整來源、各筆原圖／preview 樣本、冷暖定義與環境見 [Arch 驗證紀錄](../linux/arch-validation.md)。
